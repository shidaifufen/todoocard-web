# 网页传输回溯与对比（2026-11-24，香港时间）

## 结论与上线选择

build **2026-11-24 e** 默认使用 **A：11 月 22 日的 `7b79971` 传输流程**，提供 B/C 手动切换。这是基于用户反馈“老网页正常”选择的实机测试候选，**尚未在本轮实机验证成功，不能视为故障已修复**。

A 保留旧版的连接顺序、枚举全部服务并取最后匹配特征、通知订阅顺序、控制 `writeValue`、数据 `writeValueWithResponse`、20 块 ACK 窗口和原有等待时长。仅补充失败时释放连接和监听器、按 DataView 实际范围读取通知，以及所选特征的日志。页面外层仍限制同时发送及跨标签页连接。

图片量化、面板映射、QuickLZ、握手字节、数据索引和补齐规则均未改变。失败不会自动换版本重发图片。

## 对比测试

运行：`node --test`。历史源码按提交原样保存于 `test/fixtures/ble-history/`，manifest 中记录 SHA-256，测试不重写旧代码来适配模拟器。

完整测试通过：48 项行为测试；Node 总计报告 49 项，其中 1 项为辅助模拟器文件的加载检查。

### 相同图片与正常设备模型

七个历史版本均发送同一份 **24,686 B** 非零测试数据，补齐到 **24,720 B**，生成 **103 块**。模拟器逐字节核对数据内容、补零、块序号和握手，检查最终收到显影回执。

全部通过。控制指令均为：`01` → `02 90 60 00` → `03`；每块为 4 字节小端序号 + 240 字节图片数据。早期版本的差异在写入方式与流控，并不在这些指令字节。

### 接收缓冲与延迟回执

限制接收缓冲为 20 块、每 16 块的 ACK 延迟 40ms：

- 初版 `e8a928f` 在第 21 块触发模型的缓冲溢出，不能作为优先回退版本。
- 其余六个版本都能等待回执并完成 103 块。

这是特定条件下的模型结果，不是物理卡片的缓冲大小测量或蓝牙速度测试。

### 失败与兼容性差异

- A/B/C 在首条控制写入持续报 `Connection already in progress.` 时均失败，均不发送图片包，均释放连接。C 会尝试 5 次，A/B 各 1 次。
- 模拟双服务“第一组不可写、最后一组可写”：A 使用旧版最后匹配特征并成功，C 选第一组 FEF0 后失败。
- 模拟特征声明两种能力但显式 withResponse 报错、旧 API 可用：A/B 成功，C 失败。

后两项证明回溯对比能区分这些实现差异，**并不证明真实设备属于其中一种情况**。之前的真机记录只证明：连接、服务发现、订阅成功，首个控制写入失败；显式 withoutResponse 也未取得有效分块回执。

## 网页上的 A/B/C

| 选择 | 实现 | 用途 |
|---|---|---|
| A（默认） | `7b79971` 旧流程 + 失败清理 / 通知边界修正 | 优先验证用户曾正常使用的传输流程 |
| B | `f175352` b 版原实现 | A/B 对比服务发现及连接准备的影响 |
| C | 当前 d 版实现 | B/C 对比控制写入 API 及重试的影响 |

这些是分阶段定位的候选，不是完全只改变一个变量的实验：A 与 B 也有连接恢复、通知注册顺序和等待时间差异。结果需结合日志判断。
