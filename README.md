# 土豆片 · 网页版

纯浏览器实现的 TodooCard / T3 六色墨水屏渲染与推送：**不装软件、不上传图片**，渲染、六色抖动、QuickLZ 压缩、蓝牙传输全部在本地完成。

在线使用：https://shidaifufen.github.io/todoocard-web/

### 蓝牙配对验证与回溯测试（build 2026-11-24 g）

首次配对时，长按卡片背面按键至快闪，再点「验证配对」，选择卡片并确认系统提示。验证只读取电量特征 `180F/2A19`，完成后释放连接。安全固件要求加密链路才能读取这个特征。网页不能查询 Windows 配对记录或读取卡片的实体配对窗口。这个步骤参考 [官方 TodooCard Skills](https://github.com/Sunbelife/TodooCard_Skills/blob/81f61e1/README.md)。

手动和定时发送均使用 D。在同一次连接里读取电量、发现控制服务、订阅通知并查询分块，收到有效回执后开始发图。A、B、C 的历史流程保留用于源码回归测试。

七个历史版本已完成相同图片的模拟对比；这不代表已解决实际 Edge 蓝牙故障。图片编码、QuickLZ 和传输指令字节未修改。[历史变更、测试条件及结果](docs/BLE-HISTORY-COMPARISON-2026-11-24.md)。

在实际 Windows 卡片上已读到固件 `0xBB`，控制查询和加密电量均返回 `Insufficient Authentication`；Windows 原生配对同时失败。因此单纯回退传输版本不能修复未完成的认证。D 会在加密读取失败时停止，并标明阶段，避免继续发送图片。

## 前置条件

| 项 | 要求 |
|---|---|
| 浏览器 | **Chrome / Edge / 安卓 Chrome**（Safari、iOS 不支持 Web Bluetooth） |
| 协议 | 必须 **HTTPS** 或 `localhost` |
| 蓝牙 | 系统蓝牙打开；卡片在 1 米内、已唤醒 |
| 首次授权 | 必须由**点击按钮**触发（浏览器的安全限制） |

macOS 的 Chrome 连这张卡不稳（会弹系统配对框或 `Unsupported device`），**建议用安卓手机或 Windows Chrome**。

## 能做什么

**11 个模板**

每日一句 / 每日总结 / 今日待办 / 时间进度 / 月历 / 倒计时 / 天气 / 色块天气 / 每日诗词 / 自定义 / 照片轮播

- **色块天气**：大温度、AQI 色块、三天预报、日出日落、穿衣参考（与桌面版同一版式）
- **照片轮播**：导入时本地解析 EXIF，渲染时压一条信息带（日期/机身/参数）；没有信息就铺满整张卡
- **自定义**：标题 + 多行文本 + **二维码**（内容填链接或任意文本）

**排版**

- 字号 90%~160%、行距 60%~180%，基准都是 1.1（与桌面版一致）
- 改滑杆只重绘当前内容，不会换掉那句话/那首诗
- 诗词有「整首优先」开关：关掉大字优先并截断，打开则自动缩到放得下

**其它**

- 定时任务：页面保持打开时按时间点自动推送
- 照片库：支持多选、整个文件夹、拖拽导入；存在浏览器 IndexedDB，不上传
- 设备复用：同一个设备授权可重复使用，不用每次重新选择

---


**最近新增（网页版）**

- 照片信息带可勾选显示项（日期 / 时间 / 机身 / 参数 / 天气），勾掉即不占高度
- 收藏当前照片，「轮播方式」可选「只推收藏」
- 自定义卡片支持二维码
- 字号 / 行距两根滑杆（基准 1.1）


## 装到手机桌面（PWA）

网页版支持「添加到主屏幕」，装完像原生 App 一样全屏打开：

1. 用 **安卓 Chrome** 打开 https://shidaifufen.github.io/todoocard-web/
2. 地址栏右侧或菜单里选 **「安装应用」/「添加到主屏幕」**
3. 桌面出现「土豆片」图标，点开即用

已带 service worker 缓存外壳，**断网也能打开界面**；照片与蓝牙当然仍需要网络/硬件。

> 注意：这不是 APK。浏览器的限制决定了它**无法在后台自动推送**——蓝牙只能在页面处于前台时工作。

## 和桌面版的差别

| | 网页版 | 桌面版 |
|---|---|---|
| 模板 | 11 个 | 14 个（多 Bing 壁纸、AI 生图，色块天气两边都有） |
| 运行位置 | 浏览器标签页 | 本机服务（`127.0.0.1:8199`） |
| 图片上传 | 无（本地处理） | 无 |
| 定时任务 | 需页面保持打开 | 常驻后台 |
| 蓝牙稳定性 | 受浏览器与系统限制 | 更稳（原生 CoreBluetooth） |

网页版做不了的：Bing 壁纸（Bing 接口不给 CORS 头）、AI 生图（需要把 Key 放浏览器，不推荐）。

## 使用步骤

1. 打开页面 → 选模板 → 调参数（右侧）
2. 点 **连接卡片** → 在弹窗里选 `TodooCard` → 允许
3. 点 **推送到卡片** → 等待进度走完（约 10~30 秒）
4. 想省事就把「定时任务」打开，页面别关

传输过程中不要切后台、不要锁屏——安卓 Chrome 切后台会暂停蓝牙。

## 常见问题

**搜不到卡片**

- 卡片是否唤醒（长按背面按钮 5 秒）
- 是否已被手机 App/桌面版程序连着（同一时间只能一个连接）
- 安卓需开定位权限才能扫描 BLE

**`GATT Service no longer exists` / 连接中途断开**

链路不稳。已内置回执流控（窗口 20、6ms 间隔、写用 `writeValueWithResponse`）；仍失败就靠近卡片、插上充电再试。

**Edge 提示 `Connection already in progress`**

该错误也可能在 Edge 报告“已连接”之后出现，**包括控制特征的第一次写入**，此时尚未写入图片。2026-11-24 c 版按特征声明的能力选择 with-response 或 without-response 写法；对可安全重复的 `01` 分块查询和 `02` 长度设置，遇到 GATT 队列忙会有限退避重试。`03` 开始传输不自动重试，避免重复开始。服务和特征仅查找 FEF0 / FDF0 已授权项。日志标明具体失败阶段。

Node 模拟外围设备与独立 Edge 浏览器模拟验证了 24,686 字节 payload 的 103 个数据包、逐块回执和 `05 08` 完成确认；也验证 `01` / `02` 被拒两次后完成传输。该模拟覆盖网页协议和错误恢复，不能代替实体卡片的射频与固件测试。

请确认页面顶部是 **build 2026-11-24 g**。PWA 在线时会检查更新，断网时用本地缓存。如果验证失败，请记录日志里的具体阶段。测试时请退出其他正在连接卡片的网页或应用。

本次修复保持桌面版原有握手字节、图片量化与 QuickLZ 不变。新增连接、失败清理、重复发送、页面状态和缓存回归测试；尚需硬件实际传输确认。

**推完没刷新**

数据写完了但卡片没确认显影。等 30 秒，或再推一次。

**换设备后要重新授权**

浏览器按域名 + 设备存储授权；换浏览器或清理站点数据后需要重新点「连接卡片」。

## 本地开发

```bash
python3 -m http.server 8080
# 打开 http://localhost:8080
```

改 `js/templates.js` 里的渲染函数即可；`js/payload.js` 是 4bpp 打包与 QuickLZ，`js/ble.js` 是传输。

使用 Node.js 运行 `npm test` 可执行无需蓝牙硬件的连接生命周期与 PWA 缓存回归测试。
